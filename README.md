# quant-research-v2

量化研究与历史回测系统（加密货币 + 美股）。每日由 GitHub Actions 在 **UTC 13:00** 自动运行（多伦多时间夏令时 09:00 / 冬令时 08:00），也可在 Actions 页面手动触发。

> 本项目是研究与回测软件：**不连接券商/交易所账户、不自动下单、不承诺盈利。** 所有数据来自公开免费接口，可能存在延迟、限流或格式变化。

## 做什么

1. **资产池构建**
   - 加密货币：CoinGecko 当前市值前 50 → 映射 Binance USDT 交易对 → ccxt 拉取 2020-01-01 以来日线。
   - 美股：Wikipedia 当前 S&P 500 成分股 → yfinance 当前市值排序取前 20 → yfinance 历史日线。
2. **策略回测（单币/单股独立回测，每标的独立 10,000 初始资金假设）**
   - ADX(14) ≥ 25 为趋势状态：EMA20 > EMA50 且收盘 > EMA20 时做多；ATR 止损（2×）、止盈（3×）、追踪止损（1.5×）。
   - 趋势状态的第二个入场变体（策略类型 `donchian`，海龟/Donchian 突破）：收盘价突破此前 20 根K线最高价时做多（通道在指标层已 shift(1)，只含此前K线，无未来函数）；收盘跌破此前 10 根K线最低价通道退出，无固定止盈，ATR 止损/追踪止损兜底。同一根K线多信号同时触发时优先级为 趋势 > Donchian > 均值回归，交易记录按策略类型分别标记，可分开统计。
   - ADX < 25 为震荡状态：RSI(14) < 30 且收盘低于布林下轨时做多；触及布林中轨或 RSI 恢复至 50 退出，ATR 止损兜底。
   - 最大持仓 60 根K线兜底退出；仅做多，不做空。
3. **观察池参考层（不参与回测）**
   - ARK 六只主动 ETF 每日持仓（来源标签 `ark_daily`）。
   - SEC 13F 季度持仓（来源标签 `13f_quarterly_reference`）：默认机构列表为空，需自行在 `src/config.py` 的 `SEC13FConfig.target_ciks` 填入经 SEC EDGAR 核实的真实 CIK；持仓 CUSIP 不做代码映射（标记 `UNMAPPED`，因无免费权威映射源，不冒充已确认代码）。13F 只能使用申报日（filing_date）之后的数据，`filter_usable_as_of_date()` 强制这一纪律。
4. **产出**：SQLite 数据库 `data/quant_research.db`（runs / market_data_metadata / watchlist_members / trades / metrics 五张表）+ `results/` 目录下的 CSV/JSON（资产池快照、逐标的权益曲线、交易记录、指标汇总、运行汇总、数据质量报告 `data_quality_*.csv`、双动量筛选记录 `momentum_screen_*.csv`）。

## 数据完善与观察池筛选（v0.2.0）

- **数据质量校验**（`src/data_quality.py`）：每个标的抓取后逐项检测并记录——时间戳重复/不单调、OHLC 逻辑错误（High < Low 等）、非正价格、负成交量、零成交量、单日涨跌幅超过 ±50% 的异常波动、K线缺口（加密日线间隔 >1 天；美股间隔 >5 个日历日）、最后一根K线可能未收盘。校验**只记录告警、不修改数据**，报告写入 `results/data_quality_<market>.csv`。缺失交易日**不做前值填充**：保留缺口，指标在缺口附近自然产生 NaN 并被信号层跳过，这会使缺口附近的指标窗口有轻微偏差，属已知且接受的代价，优于伪造数据。
- **快照与可复现**：每次运行的原始抓取结果按时间戳存档到 `data/snapshots/raw/<market>/`（不覆盖历史版本）；资产池快照按日期存档到 `data/snapshots/universe/`。成分快照长期积累后可形成近似历史成分变更记录，缓解"当前名单回溯历史"不可追溯的问题（但不能消除幸存者偏差本身）。
- **流动性过滤（加密）**：最近 30 日日均成交额（收盘价×成交量）低于 1,000,000 USDT 的币种跳过并记录日志——低流动性下固定滑点假设会严重失真。阈值在 `CryptoConfig.min_avg_daily_quote_volume`，设 0 关闭。
- **最小历史长度**：历史K线少于 100 根的标的跳过并记录日志（新上市标的的指标预热不充分，硬跑只会产生噪声信号），阈值在 `DataQualityConfig.min_history_bars`。
- **双动量筛选**（`src/momentum_screen.py`）：回测前对观察池做二次筛选——相对动量（12-1 口径：回看 252 日、跳过最近 21 日）在池内排名，绝对动量（回看收益 ≤ 0）不过滤通过者不进入本次回测集合；历史不足 273 根的标的标记 `insufficient_history` 并保留。筛选只用运行日之前已完成K线的数据，被筛掉的标的同样完整记录在 `results/momentum_screen_<market>.csv`，不隐藏。参数在 `MomentumConfig`。

## 回测纪律

- 信号只用已完成K线收盘后确认，**下一根K线开盘价成交**，不使用未来数据。
- 同一根K线同时触及止盈与止损时，**止损优先**（保守假设）。
- 手续费（加密 0.1%/边，美股假设 0）与滑点（0.05%/边）在进出场均计入。
- 仓位按 ATR 止损距离定风险：单笔风险 1% 权益，单标的名义仓位上限 25% 权益。
- 胜率**从不单独报告**：始终与平均盈利/亏损、盈亏比、期望值、最大回撤一起给出；未平仓交易不计入已实现绩效。
- Sharpe 计算的无风险利率假设为 0（见 `src/config.py` 的 `RISK_FREE_RATE_ANNUAL`）。

## 已知限制（重要）

- **幸存者偏差**：加密前 50 与 S&P 500 成分股均为"当前"名单，无法还原历史时点的真实名单与排名；当前市值不代表历史市值。结果应视为方法演示与研究参考，不是无偏的历史业绩证明。
- **双动量筛选的时点属性**：筛选决定的是"本次运行回测哪些标的"，是运行时点的选择，与市值池本身一样不是历史无偏选择；跨运行比较结果时须注意每期入选集合不同。
- 单资产独立回测**不是组合回测**：把各标的权益曲线相加/平均不代表统一账户的组合绩效。
- **配对交易未实现**：配对/统计套利（Gatev, Goetzmann & Rouwenhorst, 2006）需要双资产协整检验与做空腿，与本项目"仅做多、单资产独立回测"的边界冲突，明确不在本引擎内实现；如未来开展，将作为独立的第二阶段项目，并先解决融券成本与合约做空的现实约束，不做"只做多一腿"的伪配对冒充市场中性策略。
- 免费数据源（CoinGecko/ccxt/yfinance/ARK/SEC）均可能限流、延迟或变更格式；单标的失败会被记录并跳过，不中断整体运行。
- SEC 要求请求带可识别的 User-Agent：部署时请通过环境变量 `SEC_USER_AGENT` 或仓库 Secret 设置为你自己的真实联系邮箱，不要长期使用代码中的占位值。

## 本地运行

```bash
pip install -r requirements.txt
python main.py
```

退出码：核心流程全部失败才返回非零；部分标的/数据源失败记为 `partial_failure` 并保留已完成产出，退出码为 0。每次运行的详细日志在 `results/logs/`。

## 定时运行

`.github/workflows/daily_run.yml`：每日 UTC 13:00 + 手动触发；运行后自动把更新后的 `data/*.db` 提交回仓库。需要在仓库 Settings → Actions → General 中把 Workflow permissions 设为 **Read and write**。
